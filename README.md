# Изба-читальня «У Лукоморья» на Spring

Небольшая изба, в которой видно ядро Spring: контейнер, внедрение зависимостей, настройки, REST, проверку полей, ошибки, базу, транзакции, безопасность, события и тесты. На полке двадцать томов классики, самовар пыхтит, сторож у крыльца.

Spring шире этого проекта. Здесь нет очередей, реактивного веба и микросервисов. Сначала имеет смысл довести до автоматизма то, из чего собран почти любой обычный сервер.

Стек: Java 21, Spring Boot 4.1.2. Идеи те же, что в курсах по Boot 3. Из заметных имён изменилось одно: веб-стартер называется `spring-boot-starter-webmvc`. Пакеты с `javax.*` в этом поколении не используются, в коде стоит `jakarta.*`.

## Запуск

Maven отдельно ставить не нужно: в папке лежит `mvnw.cmd`, он скачает Maven сам. Первый запуск подольше, качаются зависимости.

```powershell
.\mvnw.cmd test
.\mvnw.cmd spring-boot:run
```

Потом открой [http://localhost:8080](http://localhost:8080).

Остановка сервера в том же окне: Ctrl+C.

Пароль на запись: **student / student**. Чтение пароля не просит.

Порт занят — поменяй `server.port` в `src/main/resources/application.yml`.

## Как идёт запрос

1. Браузер или `curl` попадает в Tomcat.
2. `SecurityConfig` решает, пускать ли запрос. Чужой POST заканчивается на 401, до контроллера дело не доходит.
3. `RequestLoggingInterceptor` пишет в консоль строку `Гонец доскакал до избы MVC`.
4. Контроллер забирает JSON, путь и параметры. `@Valid` проверяет поля.
5. Сервис применяет правила библиотеки внутри транзакции.
6. Репозиторий читает и пишет H2. В профиле `dev` SQL печатается в консоль.
7. После создания книги `BookService` публикует `BookCreatedEvent`, а `LibraryEventListener` пишет о нём в лог. Сервис слушателя не вызывает.
8. Наружу уходит DTO, не сущность. Сессия базы к этому моменту уже закрыта: в `application.yml` стоит `open-in-view: false`.

При обычном запуске `main` включает профиль `dev`. Имя в `/api/info` будет «Изба-читальня «У Лукоморья» (dev, самовар ревёт)», а в консоли появится SQL. Тесты `main` не вызывают, поэтому имя там без пометки про самовар.

## В каком порядке читать

1. `pom.xml` — откуда берутся возможности и почему у зависимостей нет версий.
2. `LibraryApplication` — старт, автоконфигурация, сканирование пакета, профиль.
3. `application.yml` и `application-dev.yml` — порт, база, лимит книг, SQL.
4. `config/LibraryProperties` — свои настройки как объект.
5. `config/AppConfig` — бин из чужого класса, на примере `Clock`.
6. `greeting` — два бина одного типа и `@Qualifier`. Место внедрения смотри в `InfoController`.
7. `domain/Author` и `domain/Book` — таблицы, ключ, ленивая связь, кто хозяин внешнего ключа.
8. `repository` — Spring Data пишет реализацию по имени метода и по JPQL.
9. `service/AuthorService` и `service/BookService` — правила, транзакции, лимит из yaml.
10. `event` — публикация и слушатель.
11. `web/dto` и контроллеры — граница HTTP. В `BookController` важен порядок `/out-of-stock` и `/{id}`. Список книг приходит страницей: массив в `content`, число книг в `page.totalElements`.
12. `exception` — 400, 404 и 409 в одном формате.
13. `config/SecurityConfig` — кто читает свободно и кто пишет по паролю.
14. `web/RequestLoggingInterceptor` и `web/WebConfig`.
15. `bootstrap/DemoDataLoader` — данные после старта, через те же сервисы.
16. `src/main/resources/static/index.html` — страница, которая вызывает API.
17. `BookServiceTest` — правило без Spring. `LibraryApiTest` — весь сервер на случайном порту.

## Что сделать руками

1. Открой главную. По описи двадцать томов, имя избы с пометкой про самовар.
2. В консоли запуска найди двадцать строк `Бам, в колокол` и SQL вставок.
3. Сыщи «мир». Уйдёт запрос `GET /api/books?title=мир`.
4. Пропиши сочинителя, например Марину Цветаеву, 1892.
5. Добавь Пушкину книгу с новым ISBN из 13 цифр. В консоли будут `INSERT` и ещё одно событие.
6. Добавь книгу Толстому. Ответ 409: у него уже две книги, а `library.max-books-per-author` равен 2.
7. Удали свою книгу. Ответ пустой, статус 204.
8. Открой [консоль H2](http://localhost:8080/h2-console). JDBC URL: `jdbc:h2:mem:library`, пользователь `sa`, пароль пустой. Выполни `SELECT * FROM BOOKS`.
9. Открой [health](http://localhost:8080/actuator/health) и [info](http://localhost:8080/actuator/info). В info есть имя и лимит: это бин из `AppConfig`.
10. Запусти `.\mvnw.cmd test`.

Короткий запрос из PowerShell:

```powershell
curl.exe http://localhost:8080/api/books
curl.exe -u student:student -H "Content-Type: application/json" --data-raw "{\"name\":\"Марина Цветаева\",\"birthYear\":1892}" http://localhost:8080/api/authors
```

Форма на главной делает то же самое.

## Словарь на этом коде

| Слово | Где смотреть |
| --- | --- |
| Бин | Любой объект, которым владеет контейнер: сервис, репозиторий, `Clock`, цепочка безопасности |
| Внедрение | Аргументы конструктора. Контейнер их подставляет |
| Стартер | Зависимость в `pom.xml`, которая приносит библиотеки и автоконфигурацию |
| Стереотип | `@Component`, `@Service`, `@Repository`, `@RestController` — метки для сканирования |
| `@Bean` | Метод, который сам возвращает готовый объект. Нужен для чужих классов |
| DTO | `BookResponse` и запросы `Create*`. Форма для клиента |
| Сущность | `Author` и `Book`. Форма для базы |
| Транзакция | Метод сервиса с `@Transactional`. В конце — commit, при исключении — откат |
| Профиль | Набор настроек. Здесь `dev` включает `application-dev.yml` |
| Событие | `BookCreatedEvent`. Издатель и слушатель не ссылаются друг на друга |

Коды ответов в проекте:

- 200 — данные на месте.
- 201 — объект создан, в заголовке `Location` его адрес.
- 204 — удалён, тела нет.
- 400 — кривое поле, смотри `fields` в JSON.
- 401 — на запись не передали пароль.
- 404 — нет такого id.
- 409 — поля годные, но лимит или повтор ISBN не пускают.

## Три опыта, которые много объясняют

Убери `@Qualifier` у одного аргумента `InfoController` и запусти приложение. Старт упадёт: двух `Greeting` контейнеру достаточно, чтобы отказаться выбирать.

Поменяй `library.max-books-per-author` на 5, перезапусти и снова добавь книгу Толстому. Правило в коде не менялось, изменилась настройка.

В `BookService.update` нет `save`. После запуска измени книгу через `curl` методом PUT и посмотри `UPDATE` в SQL. Hibernate сам замечает грязное поле внутри транзакции.

```powershell
curl.exe -u student:student -X PUT -H "Content-Type: application/json" --data-raw "{\"title\":\"Война и мир\",\"publishedYear\":1869,\"copies\":7}" http://localhost:8080/api/books/1
```

id первой книги при чистом старте равен 1. Если уже что-то удалял, id возьми из списка на главной.

## Куда идти после

Когда этот путь читается спокойно, следующие отдельные темы такие:

- миграции схемы: Flyway, вместо `ddl-auto: update`;
- настоящая база: PostgreSQL тем же репозиторием, меняется URL;
- пароль в виде токена, а не Basic;
- `@TransactionalEventListener`, если реакция нужна только после commit;
- кэш и `@Async`;
- Testcontainers, чтобы интеграционный тест поднимал настоящую базу.

Каждую из них лучше добавлять отдельным маленьким шагом поверх этого проекта, а не учить все сразу.
